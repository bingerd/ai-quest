# Meridian Retail: engagement handout (fictional)

Everything in this file is made up for the workshop. It contains no real client data, so you can upload it to
your workshop project.

## The engagement

- **Client:** Meridian Retail, a fictional chain of 140 home-goods stores in the Benelux.
- **Our work:** replace the stock-replenishment process with a forecast-driven one. Twelve weeks, started
  1 September. The team is an engagement manager, two consultants and one data engineer.
- **Sponsor:** Annelies de Vries, Operations Director. Not technical, reads on her phone, wants decisions rather than
  background.
- **Steering committee:** monthly, 45 minutes. Gets a one-page status update two days before.

## Statement of work (summary)

1. Map the current replenishment process in 10 pilot stores (weeks 1–3).
2. Build and validate a demand forecast for the top 500 products (weeks 3–8).
3. Run the new process in the pilot stores for four weeks (weeks 8–12).
4. Recommend a rollout plan for all stores (week 12).

Success measure agreed with the client: fewer out-of-stocks in pilot stores, without more stock on hand.

## This month's facts (week 6)

- Process mapping is done in all 10 pilot stores, one week late because two store managers were on leave.
- The forecast beats the current method on 410 of the 500 products in back-testing. It is weak on seasonal
  garden products.
- Risk: the store-level stock data has gaps for 3 of the 10 stores. The client's IT team has promised a fix by
  week 8.
- **Decision needed from the committee:** start the pilot in 7 stores in week 8 as planned, or wait two weeks
  for all 10.

## House style for status updates

- One page. RAG status first, then progress, risks and decisions needed.
- Plain English. No consulting jargon.
- Numbers must trace back to this handout.

## The one-line requirement for the four rounds

> Write the one-page status update for the Meridian Retail steering committee.
