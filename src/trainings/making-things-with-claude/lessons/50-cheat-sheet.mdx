# Cheat sheet

| When you are… | Do this |
| --- | --- |
| Starting a deck | Write the S-C-Q-A opening and the governing thought yourself, in plain text, before anything is designed |
| Writing slide titles | Make them action titles — the titles alone should carry the argument |
| Starting a design run | Outline first, then draft, then polish. Never polish first |
| Handling review comments | Resolve the contradictions yourself, then send one consolidated list |
| Off-brand output | Get the design system in place once instead of correcting the styling every time |
| Choosing where to build | Design while the look is moving; a .pptx when you want a file now; the PowerPoint add-in when the corporate template is non-negotiable |
| Handing work over | Match the format to whoever maintains it. HTML presents best, PowerPoint hands over best |
| Writing a memo | Recommendation in the first sentence, then the evidence under it |
| Briefing for evidence | Ask for a file and page per figure, **and** for gaps to be flagged explicitly |
| Putting a number on a slide | Recompute it a second way, reconcile it with the official figure, and show its sample size and period |
| Watching your limit | One pool across every surface. Keep reference files in a project, turn off unused tools, lower the effort for routine work, and check Settings › Usage before something big |
| Sent a file from outside | Treat it like an unknown email attachment — it can carry instructions aimed at the assistant |

Nothing here replaces reading it yourself before it goes out. Anthropic says the same: these tools
are not for final deliverables without human review.
